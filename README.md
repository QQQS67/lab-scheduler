# 设备共享调度平台

> 面向高校实验室的**设备预约与调度系统**，核心解决「同一设备同时段被重复预约」的并发冲突问题。
> 采用 **时段重叠检测 + 审批状态机 + RBAC 权限** 三重机制保障数据一致性。

## 三个核心难点

### 1. 时段冲突并发控制

同一台设备在同一时段只能被一个预约占用。采用三层保障：

| 层级 | 手段 | 作用 |
|---|---|---|
| 交互层 | 前端实时检测 | 提交前即时反馈，避免无效请求 |
| 事务层 | MySQL 事务 + 排他锁 | 防止并发写入产生的竞态 |
| 存储层 | 唯一索引 `(device_id, time_slot)` | 兜底，杜绝脏数据 |

半开区间判定：两区间重叠的唯一条件是 `aStart < bEnd && bStart < aEnd`，
一条式子覆盖「部分重叠 / 包含 / 被包含」三种情况。

### 2. 审批状态机

```
pending ──> approved ──> borrowed ──> returned
   │            │            │
   │            │            └────> overdue ──> returned
   └──> rejected <──┘  └──> rejected
```

所有流转必须经过 `ALLOWED_TRANSITIONS` 校验，非法跳转直接拒绝并给出原因。
状态节点用 `Record<BookingStatus, StatusType>` 存储，新增状态时编译期即报错提醒补齐。

### 3. RBAC 权限

| 角色 | 预约 | 审批 |
|---|---|---|
| 学生 | 需审批 | 不得审批本人 |
| 教师 | 免审批直接通过 | 可审批全部 |
| 管理员 | 免审批 | 可审批全部 |

## 目录结构

```
src/
├── types/       # 全局类型定义（= 数据库表结构的蓝本）
├── utils/       # 纯业务规则：时段冲突检测、状态机、权限判定
├── mock/        # 模拟数据，后端完成后由真实接口替换
└── App.vue      # 设备列表 + 预约记录 + 实时冲突检测
```
